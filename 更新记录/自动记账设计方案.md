# PigBaby v1.6 自动记账（通知监听）设计方案

> 建立日期：2026-09-08（会话讨论定稿，待实施）
> ⚠️ 2026-09-10 更新：确认策略已由 [v2.0-设计方案.md](./v2.0-设计方案.md) 修改——捕获后一律生成"待确认"草稿，个人中心可关闭确认。本文档其余内容（架构、去重、商户规则）仍有效。
> 目标版本：v2.0 第二批（原 v1.6.0，并入 v2.0 里程碑）
> 用户场景：**个体用户**，无商户收款需求；只有两大方向——①日常支出（高频，微信/支付宝/银行卡）②转账/收款（低频，微信/支付宝间个人转账）。目标：付款/收入后 **1-2 小时内**记录自动更新到 PigBaby。

## 1. 为什么没有官方 API（结论先行）

- 微信支付、支付宝**对个人没有开放接口**，只对认证商户开放（商户平台 API v3 账单为 T+1，也不满足 1-2h，且需商户号+服务端证书+IP 白名单）。
- 个人微信/支付宝钱包内部转账**不发短信**（银行短信只覆盖绑卡消费/提现），现有短信自动记账接不到钱包流水。
- 因此可行的自动化通道只剩：**系统通知监听（NotificationListenerService）**，这是钱迹/一木记账等 App 的做法。

## 2. 已拍板的交互决策（用户选定）

| 事项 | 决定 |
|---|---|
| 支出（高频） | 通知监听捕获后 **全自动直接入账**，按商户规则打标签，默认"其他"，事后可改/删/撤销 |
| 收款/转账（低频） | **通知辅助预填**：通知内容完整 → 生成"待确认"草稿（金额/对方已填好，点一下入库）；通知缺失 → 手动快速表单兜底 |
| 短信通道 | 保留现有短信自动记账，与通知监听**交叉去重**，避免一笔两记 |
| 商户→标签 | 本地规则表 + 学习机制（手动改一次记住），**短信与通知两条通道统一用同一套规则** |
| 记账方式 | 允许为自动记账调整现有记账数据流，两条通道产物统一落 `Transaction` |

## 3. 架构与数据流

```
微信/支付宝交易
   ├─(渠道1) 系统通知 → NotificationListenerService(原生,App没开也收)
   │          过滤包名 com.tencent.mm / com.eg.android.AlipayGphone
   │          提取: 金额/对方(商户)/收付方向/时间 → 持久化原生侧(SharedPreferences)
   │          ① App 打开时 JS 拉取补录  ② App 开着时插件事件实时推送
   └─(渠道2) 银行短信 → 现有 SmsReceiver/SmsParser(保留)

        ↓ 统一入库管线（跨渠道去重：±10min + 金额 + 方向）
        ↓ 支出 → 商户规则表打标签 → 全自动写入 Transaction
        ↓ 收款 → 待确认草稿列表 → 用户点确认写入 Transaction
```

关键点：
- 通知监听是**秒级**，1-2h 富余；问题不在延迟而在**覆盖率**（通知不弹=漏单）。
- 漏单兜底（第二期）：每日定时对账或手动周导出 CSV 导入补漏。
- 商户名提取：通知文本含商户全称（比短信句式可靠）；短信侧现有句式（向X支付/在X消费/到X消费）需扩展兼容更多银行写法（如"商户名称:xx"、"网上消费(xx)"）。

## 4. 组件拆解（实施清单）

### 原生层（Android，必需手写，无现成 Capacitor 插件）
1. `NotificationListenerService` 子类：
   - manifest 注册 + `BIND_NOTIFICATION_LISTENER_SERVICE` intent-filter
   - `onNotificationPosted` 过滤包名，读 `title/extras text`
   - 正则提取：金额（¥/￥/元）、方向词（支出：支付/付款/扣款；收入：到账/收款/向你转账）、对方/商户
   - 解析结果写原生存储（SharedPreferences），App 关闭不丢
2. Capacitor 桥插件方法：
   - `openNotificationListenerSettings()`（跳系统设置，此权限**只能手动开**）
   - `checkEnabled()` / 自检
   - `pullCaptured()`（打开 App 时拉队列）+ `clearCaptured(ids)`
   - App 存活时 `notifyListeners('capture')` 推送新事件

### JS 层
3. 自动记账解析/规则引擎（可复用/扩展 `src/smsAuto.ts` 思路）：
   - 跨渠道去重（时间窗 ±10min + 金额 + 方向 + 对方）
   - **统一商户→标签规则表**：内置字典（复用现有 TAG_KEYWORDS 分类）+ 用户自定义条目 + "改过即记住"
   - 支出直接落 `Transaction`（沿用短信导入的撤销模式）；收款生成待确认草稿（独立存储 key）
4. UI：
   - Profile「权限设置」卡片加「自动记账」行：开启 → 跳通知使用权设置 + 状态自检
   - 记账页「待确认」入口（收款草稿，一键确认/忽略）
   - 「自动记账设置」：商户→标签规则查看/增删；「最近捕获」调试页（原始通知+解析结果，**测试期必看**）
5. 手动快速表单（转账/收款兜底）：金额+对方+日期，标签默认"转账"

## 5. 实施顺序

### 第一批（主体功能）
1. 原生 NotificationListenerService + 桥插件 + 权限入口
2. 捕获解析 + 原生持久化 + App 打开拉取
3. 统一入库管线（去重→支出自动/收款草稿）
4. 商户字典 v0 + 「最近捕获」调试页（校准解析用）
5. 测试：真实小额支付/转账，核对「最近捕获」与账本

### 第二批（加固）
- 国产厂商后台保活适配（小米/华为/OPPO/vivo 白名单引导）
- 漏单检测（"今日支出笔数 vs 通知条数"对不上提醒）
- 兜底对账（手动周导出导入 或 无障碍定时抓账单页，二选一评估）

## 6. 前置事实核查（测试前必做）

- [ ] 观察 1-2 天：付款/收款后系统通知栏是否出现「微信支付/支付宝」金额通知？截图记录通知文字（决定解析正则）
- [ ] 微信「微信支付」服务号是否被设为免打扰（影响通知展示）
- [ ] 支付宝「交易提醒」通知开关状态

## 7. 风险与开放问题

- 通知不弹/被合并/杀后台 → 漏单；第二期兜底解决
- 微信/支付宝通知文本变化 → 正则需维护
- 无障碍方案（可全自动抓完整账单页）作为备选，最脆，暂不采用
- 通知使用权 = 可读所有 App 通知（隐私敏感），**只解析两个目标包名**，其余不落盘不处理
